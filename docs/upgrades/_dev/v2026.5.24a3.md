# Upgrading to kairix v2026.5.24a3 (alpha)

This is a small follow-up to `v2026.5.24a2`. The single user-visible change is that the `agent_knowledge_populated` onboard check is now config-driven — you can tell it where your agent memory lives and what the file layout looks like, instead of relying on the bundled default.

If you're already on `v2026.5.24a2`, this upgrade is a straight pull with no config change required. The bundled default glob is broader than the one in earlier alphas, so most vaults that previously failed this check will now pass it without any operator action.

## What this release covers

- **`agent_knowledge_populated` onboard check reads its layout from `kairix.config.yaml`.** Two new optional keys live under `paths:`:
  - `paths.agent_knowledge_dir` — directory name under your document root that holds the agent-memory tree. Default `"04-Agent-Knowledge"`.
  - `paths.agent_memory_glob` — pattern (relative to that directory, applied recursively) that identifies memory log files. Default `"**/*.md"` — any markdown anywhere under the tree counts.
- **The default glob is broader than earlier alphas.** Previously the check required `<agent>/memory/<file>.md`. Several real vaults store memory logs directly under each agent (`<agent>/2026-05-25.md`) or under a single shared `memory/` directory, and the strict glob rejected those layouts. The new default accepts any of these shapes; operators with a stricter convention pin the old pattern via `paths.agent_memory_glob: "*/memory/*.md"`.
- **The check's failure message now names the glob it searched** so operators see at a glance whether the layout or the config is the mismatch.

## Before the upgrade

No baseline change required. The check now accepts more layouts than before, so it can only go from "failing" to "passing" — never the other direction.

## After the upgrade — pinning a stricter layout (optional)

Skip this section unless `agent_knowledge_populated` is matching files you don't want counted as agent memory.

### Pin the directory name

If your vault uses a different top-level directory:

```yaml
paths:
  agent_knowledge_dir: "team-memory"           # instead of the default 04-Agent-Knowledge
```

### Pin the glob

If you want the check to only count files that follow a specific per-agent layout:

```yaml
paths:
  # Only files at <agent>/memory/<file>.md count — the strict shape used
  # by the briefing pipeline's canonical recipe.
  agent_memory_glob: "*/memory/*.md"
```

Or, for a date-stamped convention:

```yaml
paths:
  agent_memory_glob: "*/memory/[0-9][0-9][0-9][0-9]-*.md"   # YYYY-*.md only
```

Verify the change with:

```bash
kairix onboard check                # confirm agent_knowledge_populated still passes
kairix onboard check --json | jq '.results[] | select(.name == "agent_knowledge_populated")'
```

The `detail` field in the result names the directory and the glob that were used — useful for triaging "I expected my files to count but they didn't".

## Expected drift

None. The check is purely a healthcheck — it doesn't write to the index or the topology tables, so flipping its layout has no effect on search results, ingest behaviour, or chunk routing.

## Rolling back

Remove the `paths.agent_knowledge_dir` and `paths.agent_memory_glob` entries from your `kairix.config.yaml`. The defaults take over.

## Things that haven't changed

- The briefing pipeline still reads from `04-Agent-Knowledge/<agent>/memory/` for synthesis (the config knob only affects the onboard check, not the pipeline's own resolver). The two surfaces will reconcile in a follow-up so both read from the same config entry.
- Every other onboard check. The 14 other checks are unchanged.
- Every feature flag from `v2026.5.24a2`. Pulling this version does not flip any flag.
