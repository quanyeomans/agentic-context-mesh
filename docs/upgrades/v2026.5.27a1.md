## Upgrading to kairix v2026.5.27a1 (alpha)

Three fixes that drop straight out of the v2026.5.26a1 dogfood — none require a config change.

The big one is the **markitdown converter libraries missing from the production image (#322)**. v2026.5.26a1 shipped with markitdown's PDF extra but none of the per-format converters (DOCX, XLSX, PPTX, Outlook MSG). The SharePoint dogfood produced 8,785 dead-lettered items on first run because every Office document failed extraction with `MissingDependencyException`. The Dockerfile now installs every declared extra, and a new `onboard check` step imports each declared library at startup so the same regression can't ship silently again.

The second is **silver-stage chunking for oversized paragraphs (Bug B)**. A single 2,000-character paragraph in a markdown document would land as one chunk that overshot the target. The chunker now splits oversized paragraphs at sentence boundaries, then word boundaries, then character boundaries — a three-tier fallback that keeps every chunk under the target without breaking semantic boundaries unnecessarily.

The third is **the `kairix worker reextract` subcommand (Bug D)** — operator recovery for the 122 SharePoint items still in dead-letter after the #322 hotfix shipped. Before, the only path was "delete the source and re-ingest the whole thing." Now `kairix worker reextract --source-name sharepoint` walks every dead-lettered row, re-runs extraction through the now-working extractor, and clears the dead-letter rows as they succeed.

## What this release covers

- **#322 markitdown extras in the production image.** The previous image installed `markitdown[pdf]` only; DOCX/XLSX/PPTX/MSG documents failed extraction with `MissingDependencyException`. The Dockerfile now installs `markitdown[pdf,docx,xlsx,pptx,outlook]` so every documented format works out of the box.

- **#322 onboard check for declared extractor libraries.** A new `check_extractor_libraries_importable` step in `kairix onboard check` imports every library each registered extractor declares as a dependency, at startup. Missing libraries fail the check with the install command in the remediation. Catches the same regression class as #322 before items hit the dead-letter table.

- **Bug B: silver chunker splits oversized paragraphs (`kairix/core/connectors/silver.py`).** Three new helpers (`_split_long_paragraph`, `_split_long_sentence`, `_split_long_word`) plus a pre-expansion step in `_chunk_markdown`. Paragraphs over the target size split at sentence boundaries first, then word boundaries if a sentence is still oversized, then character boundaries as a last resort. Every chunk now stays under the target without breaking semantic boundaries unnecessarily.

- **Bug D: `kairix worker reextract --source-name <name>` for dead-letter recovery.** Walks `DeadLetterStore.list(source_name)`, looks up each item's `bronze_records` row, re-runs `extractor.extract(raw, mime)` through the currently-registered extractor, runs silver → chunk_writer → entity-graph sink, then clears the dead-letter row. Commits per item so partial recovery is durable. `--dry-run` walks the same logic without committing — useful for sizing a recovery before committing to it. `--limit N` caps the number of items processed (default: all dead-lettered items for the source).

- **`DeadLetterStore.clear(source_name, item_id)`** — caller-owned transaction (matches the rest of the store), idempotent (returns False when no row existed).

## Before the upgrade

No baseline change required. The three fixes are purely additive at the API surface — same connector Protocol, same on-disk bronze layout, same chunk-writer contract.

If you ran v2026.5.26a1 against any source that included DOCX / XLSX / PPTX / MSG documents and saw a wave of dead-letter rows, **do not delete the source** — Bug D's `reextract` recovers them in-place after this upgrade.

```bash
docker compose pull

docker compose exec kairix kairix onboard check      # confirm extractor-libraries check passes
```

## Recovering dead-lettered items

If you have dead-letter rows from a pre-v2026.5.27a1 run:

```bash
# Size the recovery first (no commits).
docker compose exec kairix kairix worker reextract --source-name sharepoint --dry-run --json

# Recover for real once the dry-run looks right.
docker compose exec kairix kairix worker reextract --source-name sharepoint --json
```

The output reports four counters:

- `recovered` — extract + silver + writer all succeeded; dead-letter row cleared.
- `still_failing` — extract or downstream raised again; row kept in dead-letter with bumped failure_count.
- `skipped_no_bronze` — dead-letter row points at an item whose `bronze_records` row was already pruned (e.g. the #318 orphan reaper).
- `skipped_no_connector` — dead-letter row's `source_name` isn't in the current config (operator removed the connector but old rows remain).

## What to verify

```bash
# Onboard check should report 16/16 pass (the new extractor-libraries
# check is additive on top of the v2026.5.26a1 set of 15).
docker compose exec kairix kairix onboard check

# After reextract, dead_letter rows for the source should be near zero.
docker compose exec kairix kairix worker preflight --json | jq .dead_letter_pending
```

## Rollback

```bash
KAIRIX_IMAGE_TAG=2026.5.26a1 docker compose pull
KAIRIX_IMAGE_TAG=2026.5.26a1 docker compose up -d --force-recreate
```

Rolling back loses the new `reextract` subcommand and the onboard check, and re-introduces the missing markitdown converters. Existing chunks written by v2026.5.27a1 silver remain valid — the chunker change is purely additive.
