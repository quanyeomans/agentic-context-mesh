# Upgrading to kairix v2026.5.18

This guide tells you what to do when upgrading. It is written so an agent (or human) can follow it without external context — drop it into your reading list and the upgrade should self-manage. If you are reading this in a vendored copy of kairix your version is already current.

## What this release covers

A new ingest-and-eval architecture rolls in here. Conversational corpora — the multi-session transcripts kairix is designed to handle for iterative work with agents and teams — get end-to-end production-path coverage. A consolidated `kairix benchmark run` CLI replaces the four-way split across `benchmark`, `eval`, `probe`, and `soak`. Cold-start behaviour for HTTP-deployed kairix becomes machine-actionable for agents. Several fitness functions tighten to catch a class of test-only-injection patterns that were slipping through the prior checks.

The release is alpha-tagged for dogfooding. Existing deployments don't need to change anything to upgrade; the legacy CLIs continue to work with deprecation notices pointing at the new form.

## 1. Conversational recall

`kairix prep` now treats structured fact rows as legitimate context regardless of snippet length. Fact triplets like `"Alice role: VP of People"` are short by design — the 40-char chunk floor that protects against thin chunk text was applying to facts as well, so short factoid answers were being dropped before reaching the synthesiser. The floor now applies to chunk-tier results only.

The attribute-fact intent classifier covers two additional question shapes:

| Shape | Example |
|---|---|
| `what did X verb?` | "What did Alice research?" |
| `who is/was X's Y?` | "Who is Alice's manager?" |

Both shapes previously routed to a generic semantic intent with low fact-retriever weight; they now get the dedicated attribute-fact retrieval path.

Session-level date metadata flows into extracted facts via a new `evidence_at` field. When a session JSONL has a sidecar metadata file (or when `kairix ingest-chat --metadata` is passed an explicit metadata path), the date anchors every fact extracted from that session. Temporal questions that previously resolved to relative phrases echoed from the source ("yesterday") can now resolve to absolute dates.

## 2. `kairix eval` against conversational corpora

`kairix eval <suite>` for conversational suites previously defaulted to a null fact extractor; the suite ran cleanly but produced no facts in the SQLite store. A new module `kairix.corpus.wiring` provides the production factory functions for fact extractor, document writer, embedder, and consolidation. The eval CLI wires these in by default; the legacy null-extractor behaviour is retained behind an explicit opt-out for callers that need it.

The same `kairix.corpus.ingest.ingest_corpus` primitive runs ingestion for `kairix ingest-chat`, the eval CLI's `SuiteRunner`, and any other surface that needs to take a corpus of sessions and produce indexed documents + facts. One ingest path, one set of behaviours.

## 3. One benchmarking CLI

`kairix benchmark run` is the consolidated entry point for retrieval-quality and answer-correctness measurement.

| Flag | What |
|---|---|
| `--mode single-shot \| concurrent \| soak` | Execution mode. Single-shot lands here; concurrent and soak ship in the next release with the same suite/scorer shape. |
| `--metrics ndcg,hit5,mrr,judge,latency` | Opt-in scorers. Default is auto-selection based on which ground-truth fields appear in the suite (`gold_titles` → NDCG/Hit/MRR; `expected_answer` → LLM-judge). |
| `--scope shared\|agent\|shared+agent\|all-agents\|everything` | Collection routing for the run. |
| `--collection <name>` | Restrict retrieval to one collection (e.g. `ref-library`). |
| `--categories <c>,<c>` | Filter to a subset of query categories. |
| `--gates` | Exit non-zero when a declared release gate fails. |
| `--baseline <path>` | Compare results against a prior run's JSON output. |

The suite YAML format extends backward-compatibly. Existing NDCG suites parse unchanged. New suites can carry `expected_answer:` and `expected_answer_keywords:` alongside `gold_titles:` — the auto-scorer picks the right combination per query. Per-query `scope:` / `collection:` / `agent:` overrides are available for governance-behaviour testing.

`kairix benchmark`, `kairix eval`, `kairix probe`, and `kairix soak` continue to work. Each emits a deprecation notice on entry pointing at the equivalent `kairix benchmark run` invocation. Removal target is two releases out.

## 4. Eval scoring matches `kairix prep` scoring

`kairix eval` routes through the same `SearchPipeline` that `kairix prep` uses. Previously the eval CLI called `fact_store.search` directly, which produced scores that didn't reflect what an agent running `kairix prep` against the same query would see. The default is on (`--via-prep`); the prior behaviour is available behind `--legacy-direct` for regression comparison.

A scope-routing bug in `kairix.quality.eval.retrieval` is fixed: when an `--agent` was specified, the scope was silently set to `shared+agent` even when an explicit `--scope` was passed. Per-case scope now flows through correctly.

## 5. Cold-start for HTTP-deployed kairix

The MCP server can be alive before the retrieval stack is warm. The previous release returned a generic error during that window. This release adds a structured cold-start envelope:

```json
{
  "status": "retryable_not_ready",
  "error_code": "KAIRIX_COLD_START",
  "tool": "search",
  "retry_after_ms": 8000,
  "estimated_seconds_remaining": 8.0,
  "guidance": "kairix is warming (one-time cost per process). Retry this 'search' call in ~8 seconds.",
  "agent_instruction": "Do not answer from memory, do not use a lower-quality fallback, and do not treat this as a completed retrieval. Wait retry_after_ms, retry the same call once, then surface the cold-start blocker if it is still not ready."
}
```

A new `warm` MCP tool is callable at any time. Agents (and container entrypoints) call it at session start; subsequent retrieval tool calls return real results once warm-up succeeds. HTTP deployments defer `/healthz/ready` to 200 until the SearchPipeline is constructed and a probe query succeeds.

## 6. Diagnostic logging

Setting `KAIRIX_TRACE=1` in the environment now configures a logging handler at CLI start, so diagnostic lines from internal modules appear on stderr:

```
INFO kairix.use_cases.prep: prep.context: chunks 1/2 kept, facts 3/3 kept, 487 ctx chars
```

This is the per-query observability surface for retrieval-vs-synthesis behaviour. The default is off — production deployments stay quiet.

## 7. Fitness function additions and refinements

- **F30** (new) — every CLI subcommand in `kairix/cli.py:COMMANDS` and every `@server.tool()` in the MCP server has at least one outcome test that invokes via `subprocess.run([..., "<subcommand>", ...])` (or the MCP handler directly) and asserts on captured stdout / stderr / returned envelope content. Pre-existing surfaces are grandfathered in `.architecture/baseline/f30-operator-outcome-tests-files.txt`; the baseline only shrinks.
- **F5** (broadened) — also catches attribute access to underscore-prefixed kairix names on imported modules (`import kairix.X as alias; alias._y()`), not only `from kairix.X import _y`.
- **F6** (broadened) — also catches `*_loader`, `*_factory`, `*_builder`, `*_provider`, `*_resolver` test-injection seams in addition to the prior `*_fn` shape. Methods on `ClassDef` (the canonical Deps pattern) are exempted.
- `scripts/safe-commit.sh` now generates `coverage.xml` and runs the F7 per-file coverage check locally. The default is on; an escape hatch (`KAIRIX_SKIP_COVERAGE=1`) is available for intermediate refactor commits. CI continues to enforce F7 on push, so the escape hatch only affects local feedback latency.

## Behaviour changes worth noting

- `kairix eval` against a conversational corpus now extracts facts by default. The first run after upgrade will be more expensive than prior runs because the LLM extractor does real work. Reference-library NDCG suites are unaffected.
- `kairix benchmark`, `kairix eval`, `kairix probe`, and `kairix soak` continue to work; each emits a deprecation notice. Removal in the release after next.
- `kairix prep` accepts fact-tier snippets of any length. If an operator workflow depended on the prior chunk-floor behaviour for some reason, `KAIRIX_TRACE=1` surfaces what's being kept per query.
- `--scope` passed to `kairix prep` and `kairix search` flows through correctly when `--agent` is also set (previously silently overridden).

## Things that haven't changed

- `kairix.config.yaml` schema. The `agents:` section, provider plug-in selector, and existing fields are backward-compatible.
- MCP tool names and JSON schemas for the existing tools (`search`, `entity`, `prep`, `timeline`, `research`, `contradict`, `usage_guide`, `brief`, plus the diagnostic and operator-only tools). The new tool added in this release is `warm`.
- Authentication. kairix continues to have no built-in auth; deployments that put a gateway in front of it stay unchanged.
- Token budgets and embedding pipeline defaults.
